# alpha-blog

A small multi-user blog built with Ruby on Rails. People sign up, write short articles and manage their own profile; anyone can read.

## Stack

- Ruby 3.4.11, Rails 7.1
- SQLite in development and test, PostgreSQL in production
- Hotwire (Turbo) with import maps for JavaScript
- Bootstrap 5.3 compiled from Sass with cssbundling-rails, including toasts for flash messages
- `has_secure_password` (bcrypt) for authentication, Pagy for pagination
- RuboCop for linting

## Features

- **Accounts:** sign up, log in and log out. Usernames (3–25 characters) and emails are unique, case insensitive.
- **Articles:** a title (6–100 characters) and a description (10–300 characters). Invalid forms show the validation errors.
- **Permissions:** anyone can read articles and profiles. Only logged-in users can write, and only the author can edit or delete an article.
- **Profiles:** each user has a page with their Gravatar and their articles. Users can edit their profile or delete it, which also deletes their articles.
- **Admins:** an admin can edit and delete any article or profile.
- **Pagination:** 10 articles per page on the article list and on each profile.

## Run locally

Requirements: Ruby 3.4.11, Node.js 20.19 or newer, and Yarn (`corepack enable` installs it).

```
bundle config set --local without production
bundle install
yarn install
bin/rails db:prepare
bin/dev
```

Open `http://localhost:3000`.

`without production` skips the `pg` gem, which needs the PostgreSQL client library and is only used in production.

`bin/dev` starts the Rails server and rebuilds the CSS when a stylesheet changes. `bin/rails server` on its own doesn't rebuild it.

There is no admin screen. To make a user an admin, run this in `bin/rails console`:

```ruby
User.find_by(username: "your_username").update(admin: true)
```

## Lint

```
bundle exec rubocop
```

RuboCop is configured in `.rubocop.yml`, which excludes the files generated by Rails.

## Deploy

Live demo: https://alpha-blog-az6f.onrender.com (Render free plan: the first visit after 15 minutes without traffic takes about a minute to load).

The web service runs on [Render](https://render.com), set up with `render.yaml`. The build runs `bin/render-build.sh`, which installs gems, precompiles assets (including the Sass build) and runs migrations. The PostgreSQL database is hosted on [Neon](https://neon.com)'s free plan.

Set these environment variables in Render:

- `DATABASE_URL`: the Neon connection string.
- `RAILS_MASTER_KEY`: the contents of `config/master.key`, which is not in the repository.
- `NODE_VERSION`: 20.19 or newer, needed by the Sass build.
